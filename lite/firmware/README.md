# NF-3D Lite firmware (ESP32 + Xbox controller, v3 autonomy)

On its own the flight board flies in **angle mode**: the right stick tilts the drone and the right trigger sets the thrust. With the v3 autonomy kit (BUILD.md section 6), a XIAO ESP32-S3 Sense companion sends optical-flow and height readings. The flight board then also does **position hold**, **altitude hold**, **automatic landing**, and **AUTO**, where a laptop steers it relative to an AprilTag.

| Part | What it is | Checked how |
|---|---|---|
| `libraries/nf_core` | neuroflight-fc's portable core: Mahony filter, gyro calibration, flow/ToF Kalman filter, rate PID, mixer. Copied by `sync_core.sh`. `vehicle_params.hpp` is generated by `gen_params.py`. | neuroflight-fc's own tests, plus the tests below |
| `libraries/lite_fc` `flight_core` | `FlightCore`: estimator, angle mode, stick mapping, arming and failsafes. No hardware calls. | `tests/run.sh`: the angle law matches `lite/fly.py` to within 2e-6, plus arming tests and closed-loop tests |
| `libraries/lite_fc` `autonomy` | `PositionHold` (twin of `lite/autonomy.py`) and `Autopilot`: modes and failsafes | the position law matches the simulated one to 6e-8 over 1,600 steps. Mode-logic unit tests, and closed-loop flights with simulated flow/ToF: gusts, sticks, flow loss, range loss, link loss, AUTO, kill |
| `libraries/lite_fc` `link`, `companion` | serial protocol between the boards, flow conversion, laptop bridge | CRC check value, byte-identical vectors with the Python twin (`lite/ground/link.py`), a 2,000-frame fuzz test, and a hold flown through the real wire format (integer counts, mm) |
| `lite_fc/lite_fc.ino` | flight-board glue: MPU-6050 over I2C, 1 kHz task on core 1, 20 kHz PWM, Bluepad32, LED, companion UART (IO27 RX / IO25 TX) | compiled for the chip (`build.sh`), plus a mock syntax check |
| `companion/companion.ino` | XIAO: PMW3901 + VL53L1X at 100 Hz, VGA MJPEG stream on `:81/stream`, Wi-Fi AP `NF3D-Lite`, UDP 14560 | compiled for the chip (`build.sh`), plus a mock syntax check |
| `policy_bench/policy_bench.ino` | times neuroflight-fc's learned controller (hover_ctbr_v3, float32 and int8) on the flight board's ESP32; flash it to the bare board and read the serial monitor | compiled for the chip; the policy takes 32 kB of flash. Not part of the flight firmware (see `lite/learned.py`) |

**Both sketches compile for their real chips** with `lite/firmware/build.sh` (arduino-cli; it installs the cores and libraries on first run):

| Sketch | Core, board | Flash | RAM (globals) |
|---|---|---|---|
| `lite_fc` | esp32_bluepad32 4.1.0, ESP32 Dev Module | 767 kB of 1.31 MB (58 %) | 89 kB of 328 kB (27 %) |
| `companion` | esp32 3.0.7, XIAO_ESP32S3, OPI PSRAM | 988 kB of 3.34 MB (29 %) | 47 kB of 328 kB (14 %) |

No warnings from project code with `--warnings all`. The esp32_bluepad32 core still compiles as C++11, so `tests/run.sh` also checks the libraries and the flight sketch with `-std=gnu++11`. Sketches include `<lite_fc.h>` first: the Arduino tools only find a library through a top-level header.

## Flashing (Arduino IDE 2)
1. Under Preferences → Additional boards manager URLs, add the Bluepad32 ESP32 board package URL from the
   Bluepad32 docs ("Arduino + ESP32" section). Then install **esp32_bluepad32** in the Boards Manager.
2. Copy `libraries/nf_core` and `libraries/lite_fc` into your `Documents/Arduino/libraries/`.
3. Open `lite_fc/lite_fc.ino`, pick board **ESP32 Dev Module** and the right COM port, then press Upload.
4. Tested with esp32_bluepad32 **4.1.0**. If a newer package fails on a Bluepad32 call (`hasData`,
   `miscButtons`, `playDualRumble` or `enableVirtualDevice`), open *File → Examples → Bluepad32 → Controller*
   and use the names it uses. The Menu button is bit 2 (`0x04`) of `miscButtons()`.

## Flashing the companion (XIAO ESP32-S3 Sense)
1. In the Boards Manager, install **esp32 by Espressif** (3.x). Pick board **XIAO_ESP32S3**, and set Tools → PSRAM to **OPI PSRAM** (the camera needs it).
2. In the Library Manager, install **Bitcraze PMW3901** (1.2) and **VL53L1X** by Pololu (1.3.1). `lite_fc` and `nf_core` must be in your libraries folder too (step 2 above).
3. Open `companion/companion.ino` and press Upload. The serial monitor (115200) shows `companion: flow 1 tof 1 camera 1` and the stream address.
4. Do the flow slide test (BUILD.md section 6).

## Controls (Xbox)
- **Right trigger**: throttle in angle mode. Hover is at about 60 %.
- **Right stick**: tilt, up to 30°, in angle mode. In the hold modes it moves the drone instead, up to 1 m/s.
- **Left stick left/right**: yaw. **Left stick up/down**: climb or descend in the hold modes (up to 0.6 m/s).
- **Menu**: arm. It only arms when the trigger is released, the drone is level and still, and the battery is above 3.3 V.
- **A**: position hold. It needs the kit and the drone in the air (above 15 cm). Without flow it engages height-only hold.
- **Y**: AUTO, where the laptop steers. It needs position hold to be possible and the laptop to be sending.
- **X**: back to angle mode. It is refused unless the trigger is pulled (at least 20 %), so the drone can't drop.
- **B**: kill the motors, at any time, in every mode.

A refused button gives a short buzz on the controller.

Failsafes:
- **Angle mode**: the motors stop if the controller goes silent for 250 ms, if the drone is tilted past 75° for 0.3 s (a crash), or if it sits armed at zero throttle for 5 s.
- **Hold modes**:
  - controller silent: it lands
  - flow lost for 0.5 s: height-only hold
  - height lost for 0.5 s: it lands
  - laptop silent in AUTO: it stops after 0.5 s and goes to position hold after 2 s
  - landing: the motors stop when the ground holds the drone up, or after a timed descent if the height sensor is gone

LED on the board:
- Fast flicker: calibrating, so keep it still.
- Short blip every 2 s: no controller. Hold the Xbox pair button.
- Slow blink: ready to arm.
- Solid: armed.
- Double blink: battery low. The controller also rumbles.

## Regenerating after a design change
```
python -m lite.checks && python -m lite.fly && python -m lite.firmware.gen_params
python -m lite.firmware.tests.gen_fixture && python -m lite.firmware.tests.gen_pos_fixture && lite/firmware/tests/run.sh
```
